# 社区志愿者 AI 日常提效工具包 v0.1

> 适用对象：社区志愿者、社区公益活动组织者、关怀探访志愿者
>
> 核心原则：AI 帮助整理、生成和提醒；事实核对、关系沟通、专业判断由人负责。

## 0. 使用方法

每次使用前，先准备三类信息：

1. **目标**：这次要完成什么结果？
2. **素材**：已有的时间、地点、人物、记录、照片或原始文字。
3. **边界**：哪些内容不能猜、不能公开、需要谁审核？

通用流程：

```text
收集原始材料 → 脱敏 → 交给 AI 初步整理 → 人工核对 → 发布/归档 → 记录反馈
```

## 1. 活动通知：让居民一眼看懂

### 适用场景

社区讲座、亲子活动、义诊、志愿服务、节日活动等，需要在微信群或公告栏发布通知。

### 标准 SOP

1. 填写活动名称、对象、时间、地点、报名方式、人数限制。
2. 让 AI 生成“群公告版”和“公告栏版”两个版本。
3. 人工核对时间、地点、联系人、费用和报名链接。
4. 找一位居民试读，确认不用猜就能明白怎么参加。
5. 发布后记录报名人数和居民最常问的问题。

### 可复制提示词

```text
你是社区活动通知编辑。请把下面的信息写成一份适合微信群发布的通知。

要求：
1. 标题直接说明活动是什么；
2. 时间、地点、参加对象、报名方式单独列出；
3. 使用居民听得懂的短句，避免宣传腔；
4. 不夸大效果，不添加我没有提供的信息；
5. 最后列出发布前需要人工核对的项目。

活动信息：
活动名称：
活动目的：
时间：
地点：
参加对象：
人数限制：
报名方式：
注意事项：
```

### 输出模板

```text
【活动名称】

什么时候：
在哪里：
适合谁：
活动内容：
报名方式：
需要注意：
联系人：
```

### 验收标准

- 居民不需要追问就知道时间和地点；
- 报名方式可以直接操作；
- 关键信息没有遗漏；
- 发布前由志愿者完成最终核对。

## 2. 活动方案：从想法变成可执行安排

### 标准 SOP

1. 明确活动目标和服务对象。
2. 输入人数、场地、预算、时长和现有人员。
3. 让 AI 生成流程、物资清单、人员分工和风险预案。
4. 志愿者根据现场条件删减和调整。
5. 活动结束后记录实际人数、实际耗材和临时问题，作为下一次输入。

### 可复制提示词

```text
请为社区设计一场可执行的活动方案，不要只写宣传文案。

已知信息：
主题：
服务对象：
预计人数：
场地：
活动时长：
预算：
志愿者人数：

请输出：
1. 活动目标；
2. 分钟级流程；
3. 物资清单和数量估算；
4. 志愿者分工；
5. 老人、儿童和雨天等情况的风险预案；
6. 报名和签到方式；
7. 活动后需要记录的数据。

没有提供的数据请标记“待确认”，不要自行编造。
```

### 人工必须确认

- 场地是否允许使用；
- 物资数量和预算是否真实；
- 老人、儿童等特殊人群的安全安排；
- 紧急联系人和现场责任人。

## 3. 老人探访记录：帮问清楚、帮记下来、需要时转介

### 标准 SOP

1. 先让老人自由表达，不一开始就连续提问。
2. 按生活、安全、身体、情绪、家庭支持五个方面补充询问。
3. 记录时区分“老人原话”和“志愿者判断”。
4. 使用 AI 将记录整理为已确认、待确认、建议联系谁三栏。
5. 涉及医疗、危险、疑似诈骗或紧急情况时，立即联系家属、社区或专业机构。

### 可复制提示词

```text
请把下面的老人探访记录整理成四部分：
1. 老人原话；
2. 已确认的事实；
3. 还需要进一步确认的问题；
4. 建议联系的对象（家属、社区工作人员、医生、警方等）。

要求：
- 不进行医疗诊断；
- 不替老人下结论；
- 不补充记录中没有出现的信息；
- 对不确定内容标注“待确认”；
- 自动隐藏或提醒删除不必要的姓名、电话、住址和证件信息。

探访记录：
```

### 探访提问清单

```text
最近吃饭、睡觉和出门还方便吗？
家里有没有需要维修或存在安全隐患的地方？
最近有没有陌生人要求转账、扫码或提供验证码？
最近有没有哪件事让您特别担心或不舒服？
如果需要帮助，您最希望谁来帮忙？
```

### 安全边界

AI 只能整理信息和辅助提问，不能诊断疾病、决定用药、判断老人是否患病，也不能代替警方认定诈骗。

## 4. 活动总结：把事实沉淀成下一次经验

### 标准 SOP

1. 收集活动目标、实际人数、流程记录、居民反馈和照片说明。
2. 让 AI 按固定结构生成总结初稿。
3. 核对人数、时间、成果和居民评价，不允许虚构。
4. 把问题单独列成“下次改进清单”。
5. 选出一个可复用做法，新增到社区 AI 场景库。

### 可复制提示词

```text
请根据以下真实活动记录，生成一份社区活动总结初稿。

结构：
1. 活动背景和目标；
2. 活动时间、地点和参与情况；
3. 活动过程；
4. 居民真实反馈；
5. 做得好的地方；
6. 遇到的问题；
7. 下次改进动作；
8. 可以沉淀为场景库的经验。

要求：只使用已提供的事实；没有数据写“待补充”；不要虚构参与人数、满意度和活动效果。

活动记录：
```

### 输出模板

```text
一、活动基本情况
二、活动过程
三、参与情况
四、居民反馈
五、问题与改进
六、可复用经验
```

### 试点成功标准

- 至少完成一次真实活动试用；
- 四类场景各有一条实际记录；
- 平均文字整理时间减少 30% 以上；
- 志愿者认为至少两个场景愿意继续使用；
- 没有发生隐私泄露、事实错误或未经审核发布。

## 6. 版本迭代规则

- v0.1：完成四类基础 SOP、提示词和模板；
- v0.2：加入一次真实活动数据和常见错误；
- v0.3：根据志愿者反馈简化输入字段；
- v0.4：接入网站反馈、复制次数和模板下载统计。

每次迭代只回答三个问题：

1. 哪一步真的节省了时间？
2. 哪一步仍然需要人工判断？
3. 下一次能否让第一次使用的人也做成？
